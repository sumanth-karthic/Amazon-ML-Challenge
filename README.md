# Amazon ML Challenge 2026: Business Entity Resolution

This repository contains the completed solution for the Amazon ML Challenge 2026. The challenge involves large-scale **Entity Resolution (ER)**: given business records from three independent, noisy data sources, the goal is to determine which records across the sources refer to the same real-world business entity. 

Source 1 is the deduplicated reference source. The objective is to identify all matching records from Source 2 and Source 3 for each Source 1 entity. 

## 🏆 Project Architecture & Methodology

The solution uses a highly optimized, two-stage machine learning pipeline consisting of a **Blocking/Candidate Generation** stage and a **Pairwise Scoring** stage, designed to scale across 80.8 million possible cross-source combinations.

### 1. Preprocessing
Text fields (business names, addresses) contain severe noise (typos, different formatting, missing fields). 
- Standardization of abbreviations and legal suffixes (e.g., "LLC", "Pvt Ltd").
- Punctuation removal and unicode normalization.
- Handling of missing address fields with dedicated imputation/flags.

### 2. Blocking Strategy (Candidate Generation)
Comparing every Source 1 entity against every Source 2 and Source 3 entity is an $O(N \times M)$ operation, which is computationally intractable. We implemented a **Scalable Sparse-Matrix Blocker (V2.2)**:
- Uses a **TF-IDF vectorizer** over character n-grams (unigrams to 5-grams) and word tokens.
- Constructs inverted indexes utilizing **SciPy Sparse Matrices** for high-speed candidate retrieval.
- Retrieves the top $K=150$ most similar candidates for each Source 1 entity.
- Achieves ~93% Candidate Recall while pruning the search space by over 99.9%.

### 3. Feature Engineering
For every candidate pair generated by the blocker, we extract a rich set of string similarity and matching features:
- **String Distance Metrics:** Jaro-Winkler, Levenshtein distance, Token Sort Ratio, and FuzzyWuzzy ratios on both name and address fields.
- **TF-IDF Cosine Similarity:** Quantifies structural overlap in names and addresses using the pre-computed IDF dictionaries to properly weight rare terms.
- **Categorical & Heuristic Flags:** Exact name match flags, address missing flags, and country match flags.
- **Blocking Score:** The original TF-IDF sum score and rank from the blocking stage.

### 4. Classification Model (LightGBM)
The extracted features are fed into a **LightGBM Binary Classifier** which predicts the probability that a candidate pair is a true match.
- Trained on a deterministically sampled validation and train set using early stopping.
- Extremely fast inference using `generate_features_batch()` to avoid Pandas overhead during the 80.8M pairwise comparisons.
- The final acceptance threshold is optimized via empirical validation to strictly prioritize Precision over Recall (due to the F0.5 metric). The optimal threshold was found to be `P >= 0.98`.

## 📏 Evaluation Metric
The challenge uses the **Macro $F_{0.5}$ Score** at the entity level:
- $F_{0.5} = \frac{1.25 \times Precision \times Recall}{0.25 \times Precision + Recall}$
- The $F_{0.5}$ metric explicitly penalizes False Positives more than False Negatives, hence the high model confidence threshold.

## 💻 Setup & Usage

### Prerequisites
- Python 3.10+
- `pip install -r requirements.txt`

### Repository Structure
```
├── dataset/                    # Ignored: Original competition data
├── models/                     # Ignored: Saved LightGBM checkpoints and indexes
├── output/                     # Ignored: Predictions and inference outputs
├── src/                        # Main source code directory
│   ├── preprocessing.py        # Normalization and string cleaning
│   ├── blocking_v2_2.py        # High-speed TF-IDF Sparse Matrix Blocker
│   ├── matching_features.py    # PairFeatureGenerator for ML
│   ├── train_lightgbm.py       # Model training pipeline
│   ├── checkpointed_inference.py # Multi-threaded 80M inference pipeline
│   └── evaluate_blocking_v2_2.py # Candidate recall evaluation
├── utils/
│   └── validate_submission.py  # Official Kaggle format validator
├── CHALLENGE.md                # Official challenge problem statement
└── README.md                   # This file
```

### Running the Pipeline
*Note: Ensure the dataset is unzipped into `dataset/` before proceeding.*

1. **Train Model:**
   ```bash
   python src/train_lightgbm.py
   ```
2. **Run Full Inference:**
   ```bash
   python src/checkpointed_inference.py
   ```
3. **Validate Output:**
   ```bash
   python utils/validate_submission.py --matching output/threshold_tests/matching_098.tsv
   ```
